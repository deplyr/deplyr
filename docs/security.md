# Security

## One account

An instance has exactly one account, created on first visit. Sign-up is closed
afterwards. There is no public registration.

## Passwords and sessions

- Passwords are hashed with **argon2id**.
- A login creates a signed session token (JWT) in an `HttpOnly` cookie, valid for
  30 days.
- Login attempts are rate limited: after 8 attempts within 15 minutes, that combination of address and
  email is blocked until the window ends.

## Encryption at rest

Everything sensitive is encrypted with **AES-256-GCM** using the instance's
`DEPLYR_MASTER_KEY`:

- GitHub tokens
- SSH credentials for extra servers
- Environment variable values
- Database passwords
- Notification webhook URLs

The key is generated by the installer and kept in the instance's `.env` file. **Back
it up.** Without it, encrypted values cannot be read.

Secret values are never written to logs.

## Agents

Each server's agent has its own token, stored only as an argon2id hash. The agent
connects outward. Extra servers need no open inbound management port.

## Network exposure

| Port | Used for |
|---|---|
| 80, 443 | The dashboard and every app, through Caddy |
| 4000 | Only needed for extra servers' agents and GitHub OAuth callbacks |

Postgres and Redis (Deplyr's own) are not published to the host. Databases you
create for your apps bind to `127.0.0.1`.

## Webhooks

Notification webhook URLs are only accepted for Discord and Slack's real hosts, so
a saved URL can't be used to make the server call arbitrary addresses.

## Your apps

Environment variables are kept in a file outside the source tree and passed to the
container. They are not written into image layers.

Apps on the local server run on the same Docker host as Deplyr itself. For code you
don't trust, use a separate server.
